# Agent Instructions

This is a pnpm monorepo proof-of-concept for warehouse mobile/Android flows: `apps/web` (Nuxt 3 client, shipped to Android via Capacitor), `apps/backend` (`@warehouse/backend` — Hono + Drizzle + PostgreSQL backend holding the revised target WMS schema, :3002), and `apps/admin` (desktop admin console). The web app always talks to `apps/backend` over HTTP through a single adapter layer. The retired `apps/api`, native `apps/android` (Kotlin POC), and `packages/shared` were deleted 2026-07; their history lives in git and the `docs/superpowers/` specs.

## Tech stack

- **Workspace:** pnpm monorepo — `apps/web`, `apps/backend`, `apps/admin`, `layers/i18n` (shared Nuxt i18n layer extended by `apps/web` and `apps/admin`: `@nuxtjs/i18n` config, `i18n/locales/{en-US,zh-CN,zh-HK}.ts`, `components/LanguageSwitcher.vue`, `plugins/locale-persistence.client.ts` persisting the `warehouse-locale` localStorage key; apps add only `extends: ["../../layers/i18n"]`)
- **Backend:** `apps/backend` (`@warehouse/backend`) is the next-gen Hono + Drizzle + PostgreSQL backend holding the revised target WMS schema (full flow API per `docs/backend/api-design.md`; the web client runs against it). Table-by-table schema contract: `docs/backend/schema-tables.md` (Drizzle source of truth: `src/db/schema/*.ts`; every table has an `id` text PK — UUID v7 via `newId()` in `src/db/id.ts` / `app_uuid_v7()` in SQL, except the bigserial event-cursor tables and the `BOX-*` box labels — and carries `created_date`/`last_update_date` — `parts`/`suppliers`/`supplier_profiles`/`org_info` name it `creation_date`). Design specs for everything below: `docs/superpowers/specs/`.
  - **Master data:** `supplier_profiles` for PDA-local supplier fields (`qr_template`/`qr_template_config`/`qr_type`/`qty_encoding`), lookups `country_list`/`box_size_list`/`net_weight_formula`/`customer_profiles` (+`rule`); `suppliers` stays a pure AP_SUPPLIERS sync mirror; `parts.part_no` is NOT unique (a supplier part number can appear under several WCL item numbers) — `wcl_item_no` is the NOT NULL UNIQUE business key, other tables carry `part_no` as plain text (no FK), the UUID `id` is internal-only, `brand` a plain-text copy of the supplier code (no FK).
  - **Stock partitioning:** one standalone instance per warehouse (no `warehouse_code`); stock is partitioned by `org_id` (integer office id, 2 = HK) + `sub_inventory_code` (FK → `org_info`, composite UNIQUE `org_id`+`secondary_inventory_name` under an `id` PK; composite-FK target of all stock/doc tables; seeded master = 151 real Oracle groups from `new_seed/ORIGINAL_ID + ORG_ID + Sub Inventory mapping.xlsx` + demo groups). Cross-store sharing: `sub_inventory_share_members` (org_id+code → share_group; allocation also matches sources whose sub-inventory shares the demand's group). The pair is carried by `shelf_boxes` (nullable; put-away stamps lots with the BOX's pair), `receiving_invoice_items` (item-level since 2026-08-18 — order/invoice-level `sub_inventory_code` columns dropped; `receiving_orders.org_id` stays NOT NULL DEFAULT 2; a NULL item pair is skipped + logged by allocation until Sean's ingest-time defaulting rule lands; order/invoice supplier refs are `supplier_code` FK → `suppliers(code)`), `inventory_lots`, and `picking_orders` (nullable — allocation matches on the pair when present, org-agnostic otherwise). Natural keys: `receiving_orders.batch_no`, `picking_orders` caller-supplied UUID `id` (`order_no` is NOT unique — sync/dedup keys on the id, no `external_id`), `parts.wcl_item_no` (NOT NULL UNIQUE; `part_no` not unique), `receiving_invoice_items.line_qty` (nullable)/`ctn_no` (Oracle parity). Also 2026-08-18: `parts.default_coo` dropped (the remote `wms_parts` has none; COO prefill removed), `receiving_invoice_items.order_data` jsonb passthrough added (mirrors `additional_data`), and `picking_items.line_id`/`line_number`/`shipment_number` are nullable (upstream may omit them).
  - **Auth:** JWT bearer (HS256 via `hono/jwt`, secret env `AUTH_SECRET`, 12 h TTL — `POST /auth/login` → `{user, token}`, `GET /auth/me`); global middleware enforces the token on all routes except `/health`, `/auth/login`, `/dev/*` (`?token=` accepted only for `GET /events`); scrypt-hashed passwords (`src/auth/password.ts`, lazy upgrade of legacy plain-text rows); users↔groups many-to-many via `user_groups` + `user_group_members`; mutation actor is taken from the token, never the body. When `DOCPAL_URL` is set, login is delegated to the DocPal API (`src/auth/docpal.ts`: `POST $DOCPAL_URL/auth/login` + `GET /dms/user/getApplication`) — the local `users` row is auto-provisioned on first login (`password_hash = ""` sentinel, display name refreshed each login), DocPal `groupId`s are mapped to local codes via `docpalGroupMapping` in `src/config.ts` (`administrators`/`WMS_Admin_Group_(HK)` → `admin`+`PDA Group`, `WMS_PDA_Group_(HK)` → `PDA Group`, dashboard/email groups → none; membership replaced on every login, users with no mapped group get 403 at login), and local scrypt login only applies when `DOCPAL_URL` is unset (spec `docs/superpowers/specs/2026-08-13-docpal-auth-design.md`). Boot logs `[auth] login mode: ...` plus a `[docpal] connectivity check` reachability probe (`logDocpalConnectivity` in `src/auth/docpal.ts`) so container → DocPal network failures show up in the log before the first login; per-attempt failures log the OS-level reason under `[docpal]`/`[auth]`. User/group management lives in DocPal — there is no admin-console or API user/group CRUD and no change-password endpoint.
  - **Flow API** (full route catalog: `docs/backend/api-design.md`; SSE event catalog: `docs/backend/README.md`): `/health`; receiving (`/receiving-orders*`, mismatch CRUD under `/receiving-invoice-items/:id/mismatch*`); the shared detail aggregate (`GET /receiving-orders/:id/put-away`) carries the per-item suggestion (`suggestedShelfCode`/`suggestedBoxId`/`suggestionReason`, ranked same-part open box → same-part stock shelf → sub-inventory-matched shelf via the advisory `shelves.sub_inventory_codes`, specs `docs/superpowers/specs/2026-08-10-put-away-tasks-design.md` + `2026-08-12-put-away-shelf-org-suggestion-design.md`)); picking (`GET /picking-orders`, item scan, whole-box claim `POST /picking-orders/:id/claim-shelf-box` — reuses a shelf box whose `inventory_lots` contents exactly match the remaining demand, prefilled from receiving-line `additional_data`, `shipping_boxes.source_shelf_box_id` recorded — `/packages/:id`, `/shipping-boxes/:id*` (packing a box prefills its NULL box size/weights from the source cartons' `additional_data` — same prefill the whole-box claim applies), finish → `{id, status}` (no next-step task — box-scoped design), `report-issues`/`resolve-issue` — an issued order is frozen until resolve returns it to `pending` and re-allocates); measuring (`GET /measuring-boxes(+/:id)` — no tasks: closing a box IS the measuring completion, so the list is the open boxes containing packages; a box may hold packages from several orders (cross-order packing, `POST /shipping-boxes/:id/scan` resolves a barcode across all orders); weights kg end-to-end, `suggestedNetWeightKg` from `net_weight_formula`); verify (`/verify-tasks*` — one task per box (`shipping_box_id` unique), spawned by `closeShippingBox` when the verify step is on; second full re-scan pass over the box; `picking_packages.verify_verified` re-scan flag alongside `verified`; box-scoped reopen resets both); shipping feed for admin (`GET /shipping-orders` — per-box: closed unshipped boxes gated on the box's completed verify task when verify is on; `GET /shipping-orders/:boxId`; `POST .../:boxId/ship` stamps the box and derives order `shipped`, emits `shipping_box.shipped`); flow config (`GET /config` → `{flowSteps, pickingAllocation}` from the `warehouse_config` row `"flow"` — seeded per warehouse, merged over defaults, validated at boot; admin-editable via the console's `/flow-config` page (`GET/PUT /admin/flow-config`, runtime-applied on save — no restart — unless the `FLOW_CONFIG` env JSON override is set, which still wins over the row; ## Common commands

```bash
pnpm install        # install dependencies
docker compose up -d  # start the shared local Postgres service (required for dev/tests)
pnpm dev:backend                     # start the backend dev server on :3002 (@warehouse/backend)
pnpm build:apk                       # signed release APK pointed at the fixed web host (PRODUCTION_URL + :3000; the first-launch /server picker chooses only the backend API); publishes apps/backend/public/apk/warehouse-pda.apk + version.json
pnpm --filter @warehouse/backend test    # backend test suite (node:test; needs Postgres + TEST_DATABASE_URL)
pnpm --filter @warehouse/backend build   # backend typecheck (tsc)
pnpm --filter @warehouse/backend db:generate  # generate Drizzle migrations after schema changes
pnpm --filter @warehouse/backend db:seed      # wipe and re-seed the demo dataset
pnpm --filter @warehouse/web dev     # start web dev server on :3103
pnpm --filter @warehouse/web test    # web test suite (vitest)
pnpm --filter @warehouse/web nuxt prepare   # generate Nuxt types; run after schema/template changes
pnpm --filter @warehouse/web build   # production build
pnpm --filter @warehouse/web generate     # static export for Capacitor
pnpm --filter @warehouse/web cap:sync     # copy web assets into native platforms
pnpm --filter @warehouse/web cap:android  # bundled build: generate, sync (server URL off), and open Android project
pnpm --filter @warehouse/web cap:android:proxy  # adb reverse tcp:3103+3002 (re-run after device reconnect)
pnpm --filter @warehouse/web cap:android:dev  # proxy + sync Android pointed at the running web dev server (live reload)
```

The web dev workflow needs TWO servers: `pnpm dev:backend` (:3002) and `pnpm --filter @warehouse/web dev` (:3103). The web app always talks to the backend.

### Postgres setup (shared)

`docker compose up -d` starts the shared PostgreSQL service. Backend migrations are applied automatically on startup; `pnpm --filter @warehouse/backend db:generate` generates migrations after schema changes. Backend tests use the `TEST_DATABASE_URL` database (default `warehouse_backend_test`) and run serially because they share one test database.

For Android live reload, `capacitor.config.ts` defaults `server.url` to `http://127.0.0.1:3103`, and `adb reverse` tunnels the device's loopback ports back to the dev machine: run the web dev server and backend, then `pnpm --filter @warehouse/web cap:android:dev` — it runs `scripts/cap-android-proxy.mjs` (`adb reverse tcp:3103` + `tcp:3002`, so the default `apiBaseUrl` works on-device too), syncs, and opens Android Studio. Re-run `cap:android:proxy` after every device reconnect/reboot (`adb reverse` does not persist). Reinstall the APK after changing `capacitor.config.ts` — the config is packaged into the APK assets. Known issue: live reload may fail with a native bridge `Cannot read properties of undefined (reading 'triggerEvent')` error; use the bundled build below in that case.

Device networking notes (bundled builds verified on a real device):

- `capacitor.config.ts` sets `server.androidScheme: "http"` — required so LAN `http://` API calls are not blocked as mixed content. `AndroidManifest.xml` carries `android:usesCleartextTraffic="true"` for the same reason.
- Never run `pnpm generate` while the web dev server is running: both share `.nuxt/dist/client`, and the dev server pollutes the static export with dev URLs (`@vite/client`, absolute-path entries). Stop the dev server first, then generate.
- **`127.0.0.1` vs `localhost` on devices.** The defaults use `127.0.0.1` because some ROMs' WebViews (observed on the NLS-MT95, Android 11 / WebView Chrome 114) fail to resolve `localhost` — every fetch dies with `TypeError: Failed to fetch` and the app shows the server-down overlay even though `adb reverse` is set and the backend is healthy. To check a new device, do NOT test in the device browser (standalone Chromium hardcodes `localhost` → loopback, so it lies) — test inside the app's WebView via CDP: find `webview_devtools_remote_<pid>` (`adb shell cat /proc/net/unix | grep webview_devtools`), `adb forward tcp:9333 localabstract:webview_devtools_remote_<pid>`, get `webSocketDebuggerUrl` from `curl http://localhost:9333/json`, then over that websocket send `Runtime.evaluate` (`awaitPromise: true`) for `fetch('http://localhost:3002/health').then(r=>r.status).catch(e=>''+e)` and the same with `127.0.0.1`. If `localhost` fails and `127.0.0.1` returns 200, the device needs the numeric defaults.

### Production docker stack

`docker-compose.prod.yml` runs the full stack — db + backend + web (PDA SPA) + admin console — as a separate compose project (`warehouse-prod`) so it coexists with the dev db on :5432. Per-app Dockerfiles (`apps/{backend,web,admin}/Dockerfile`, build context = repo root, pnpm via corepack): backend is `tsc`-compiled (`node dist/server.js`, migrations auto-apply; `src/db/seed-parts-data.json` copied into `dist/db/` for the runtime seed); web/admin are `nuxt build` SPAs served by the nitro node server — `apiBaseUrl` is public runtime config, overridable at container start with `NUXT_PUBLIC_API_BASE_URL` (no rebuild). Required env: `POSTGRES_PASSWORD`, `AUTH_SECRET`; optional: `CORS_ORIGINS`, `SYNC_DB_PASSWORD` (for the external `warehouse_sync` DB role), `WEB_API_BASE_URL`/`ADMIN_API_BASE_URL`, `FLOW_CONFIG` (optional flow config JSON override of the `warehouse_config` row `"flow"`; legacy `FLOW_STEPS_DISABLED` still works, deprecated), `WAREHOUSE_SEED=off`, `WAREHOUSE_SEED_ORDERS=on` (demo receiving/picking orders are skipped by default in prod; `on` restores them). Ports: web 3000 (host; the container's nitro server listens on 3103, mapped `3000:3103`), admin 80, backend 9002; the prod db is not published to the host; `DEV_ROUTES=off` is set. When `PRODUCTION_URL` (scheme + host, from the root `.env`, e.g. `https://mobile-wms-admin.wclsolution.com` or `http://192.168.1.10` — no port) is set, web/admin `NUXT_PUBLIC_API_BASE_URL` default to `${PRODUCTION_URL}:9002` (backend CORS defaults to allow-all, so no per-origin config is needed). The backend also mounts `./apps/backend/public/apk:/app/public/apk:ro` so the APK published by `pnpm build:apk` is served in-container without a rebuild.

```bash
POSTGRES_PASSWORD=... AUTH_SECRET=... docker compose -f docker-compose.prod.yml up -d --build
```

### Native Android build / install on a connected device

When the web assets have changed, regenerate and sync first. `capacitor.config.ts` defaults `server.url` to the dev server, so bundled syncs must go through the helper script (it sets `CAPACITOR_SERVER_URL=off`; set `NUXT_PUBLIC_API_BASE_URL` to the hosted backend first for production builds):

```bash
NUXT_PUBLIC_API_BASE_URL=http://<backend-host>:3002 pnpm generate
node scripts/cap-android-bundled.mjs
```

Then build and install the debug APK (from the `android` directory):

```bash
export JAVA_HOME='/c/Program Files/Android/Android Studio/jbr'
export PATH="$JAVA_HOME/bin:$PATH"
./gradlew :app:installDebug
```

**Production release APK.** `pnpm build:apk` (repo root, script `apps/web/scripts/build-android-apk.mjs`) builds a signed release APK pointed at one fixed web host (stop the web dev server first — the script refuses to run while it is up). The sync sets `server.url = ${PRODUCTION_URL}:3000` (root `.env`, scheme + host; the prod web container port), so the WebView boots directly from the hosted app and the Capacitor bridge — injected for exactly that origin — keeps the native plugins (hardware scanning, camera capture, back button) working; a runtime WebView redirect to another host would lose the bridge, which is why the retired boot-redirect picker broke scanning. The first-launch `/server` picker (`middleware/00-server-host.global.ts`) now only chooses the **backend API** (5 regional backends on `:9002` in `utils/serverHost.ts`, saved as `pda-server-host` in localStorage and applied everywhere via `getApiBaseUrl()`; stale `:3000`/`:3103` web-host values from old builds are discarded on read; the login page's "change server" button reopens the picker, spec `docs/superpowers/specs/2026-08-13-backend-server-picker-design.md`). On first run it generates the release keystore (`apps/web/android/app/warehouse-release.keystore`) and `apps/web/android/keystore.properties` with random passwords — both gitignored; keep them, Android only treats a new APK as an in-place update when the signature matches (`versionCode` auto-increments per build for the same reason). The APK + a `version.json` are published to `apps/backend/public/apk/` (gitignored) and served by the JWT-protected `GET /admin/app-download/file`; admins download it from the admin console's `/app-download` page (Settings section). Because the WebView loads the hosted site, web content updates with every deploy — only native changes (or a web-host move) need a new APK.

If `adb` is not on your `PATH`, use the SDK recorded in `android/local.properties`. On this machine that is `'/d/android/platform-tools/adb.exe'` (e.g. `'/d/android/platform-tools/adb.exe' devices`). To clear old debug/output images from the app cache: `'/d/android/platform-tools/adb.exe' shell "run-as com.docpal.warehousedemo sh -c 'rm -f cache/debug_* cache/rectangle_*'"`.

## Code conventions

- Follow existing patterns. Make minimal, focused changes.
- Keep files small and single-responsibility.
- Put Vue composables in `composables/` and shared helpers in `utils/`.
- New data access goes through `WarehouseService` (`useWarehouse()`), which talks HTTP to `apps/backend` (:3002). List pages reload on `onMounted` plus `visibilitychange`/`focus` events so Capacitor behaves correctly; prefer the shared `useVisibleReload(load)` composable for this lifecycle wiring.
- Use shared presentation primitives on detail pages: `DetailRow`, `ScanFab`, `EmptyState`, and composables `useStatusBadge`, `useLabelScanReview`. Status badges are rendered inline with `badgeClass` and `useStatusBadge` / `statusLabel` helpers. Keep page-specific sub-views in `components/<page>/`.
- Prefer explicit, readable names over clever abstractions.

## Testing

- Backend: `pnpm --filter @warehouse/backend test` (node:test, needs Postgres).
- Web: `pnpm --filter @warehouse/web test` (vitest).

Also verify work with:

1. `pnpm nuxt prepare` — ensure types generate without errors.
2. Manual browser check — with `pnpm dev:backend` (:3002) running, log in as `operator` / `DocPal2026!`, navigate through the affected flows, and confirm behavior.

## Feature workflow

For non-trivial changes:

1. Write a design spec in `docs/superpowers/specs/YYYY-MM-DD-<feature>-design.md`.
2. Write an implementation plan in `docs/superpowers/plans/YYYY-MM-DD-<feature>.md`.
3. Implement, verify, and commit.

## Documentation system

The project maintains a dual-audience documentation system under `docs/app-docs/`: a human training manual for operators/trainers, and an AI lookup reference for coding agents.

- **Use:** start with `docs/app-docs/README.md` (TOC); `docs/app-docs/ai/feature-registry.md` locates which files implement a feature; `docs/app-docs/ai/code-map.md` maps pages/components to source files; read the relevant flow's `ai-scope.md` before changing behavior (boundaries, known limitations).
- **Maintain:** when you add, remove, or significantly change a feature, update the relevant `docs/app-docs/flows/<flow>/` files (`overview.md` concepts, `steps.md` operator steps, `ai-scope.md` scope/key files/limitations/specs), plus `ai/feature-registry.md` and `ai/code-map.md` if files or features changed. Use `docs/app-docs/ai/scope-remark-template.md` for new AI scope blocks. Do not duplicate `README.md` or `AGENTS.md`; link to them instead.

## Demo limitations to keep in mind

- **Demo passwords only.** The seed uses well-known demo passwords (`operator` / `DocPal2026!`, `admin` / `DocPalAdmin2026!`) — scrypt-hashed at seed time, but change them before any real deployment.
- **Native scanning.** The Android native `RectangleDetection.scanLabel()` flow is still used for camera-based label capture where implemented.
- **Hardware scanner delivery.** The Capacitor app receives hardware scans two ways: the `ScannerBroadcast` plugin (`apps/web/android/.../ScannerBroadcastPlugin.java`, wrapped by `composables/useScannerBroadcast.ts`) listens for the scanner service's intent broadcast `com.wclsolution.docpal.action.BARCODE_SCANNED` (extra `barcode`) and is the fast path; `useHardwareScanner` keeps the keyboard-wedge fallback (key events buffered until Enter) for browser dev and unconfigured devices. The plugin receives via a context-registered receiver plus the manifest component `ScannerBroadcastReceiver`; both share one dispatch path that suppresses duplicate deliveries of the same value within 400 ms, and the composable eats wedge key echo for 1.5 s after a broadcast scan so "Output to broadcast/keyboard" mode does not double-scan. Device setup (one-time, scanner Function settings): output mode = "Output to broadcast", PackageName = `com.docpal.warehousedemo`, ClassName = `com.docpal.warehousedemo.ScannerBroadcastReceiver`, Scan Result Action = the action above (Enable Intent ON), Data Key = `barcode` (the firmware's misspelled default `bacode` is also accepted); verify with `adb logcat -s ScannerBroadcast` (this ROM suppresses DEBUG lines — the plugin logs at INFO).
- **Capacitor web assets.** Bundled builds: `pnpm generate` then `node scripts/cap-android-bundled.mjs` (sets `CAPACITOR_SERVER_URL=off`) so the native app receives the static build from `.output/public`. For dev live reload, use `pnpm cap:android:dev` instead.
- **Android only.** iOS platform is not configured.
- **Server-down handling.** Two layers: (1) WebView can't load the app at all (web host down) — `server.errorPath: 'maintenance.html'` in `capacitor.config.ts` shows the bundled `public/maintenance.html`, which retries the build-stamped app URL on a manual button press (no auto-retry, no host override — navigating the WebView to another origin loses the Capacitor bridge); (2) app loads but the backend API is down — `composables/useServerHealth.ts` (started in `app.vue` once a backend is chosen) polls `GET /health` every 20 s + on resume, `apiClient` reports fetch-level failures to it, and `components/ServerDownOverlay.vue` covers the screen until the backend recovers, with a native-only "change server" escape to the `/server` backend picker (the overlay never covers `/server` itself).
