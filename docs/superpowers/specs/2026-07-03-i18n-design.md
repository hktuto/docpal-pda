# Internationalization (i18n) — Design Spec

## Goal

Add full i18n support to the warehouse PDA demo with three locales:

- `en-US`
- `zh-CN`
- `zh-HK` (default)

All user-facing strings in the UI are translated, including dynamic labels that come from database status codes and error messages. URLs remain in English to keep the change low-risk for a demo app.

## Decisions

| Topic | Decision |
|-------|----------|
| URL strategy | Keep existing English paths (`/receiving`, `/picking`, …). Use `@nuxtjs/i18n` `strategy: 'no_prefix'`. |
| Language switcher | Add a dropdown in `AppHeader`. Users can switch at any time. |
| Preference storage | Persist the chosen locale in `localStorage` under the key `warehouse-locale`. |
| Locale files | One JSON file per locale in `i18n/locales/{en-US,zh-CN,zh-HK}.json`. |
| Default locale | `zh-HK`. If no saved preference exists, the app starts in `zh-HK`. |
| Date / number formatting | Keep the existing simple formatting. Do not introduce locale-aware date/number formatting in this pass. |
| Status codes | Database still stores raw codes (`pending`, `open`, …). The UI maps codes to translated labels using a small helper. |
| Error messages | DB / composable errors are mapped to translation keys before display. Unknown errors fall back to the raw message. |

## Architecture

### 1. Nuxt module

Add `@nuxtjs/i18n` and register it in `nuxt.config.ts`:

```ts
i18n: {
  strategy: 'no_prefix',
  defaultLocale: 'zh-HK',
  locales: [
    { code: 'en-US', name: 'English', file: 'en-US.json' },
    { code: 'zh-CN', name: '简体中文', file: 'zh-CN.json' },
    { code: 'zh-HK', name: '繁體中文（香港）', file: 'zh-HK.json' },
  ],
  langDir: 'i18n/locales/',
  detectBrowserLanguage: false,
  vueI18n: './i18n/config.ts',
}
```

`i18n/config.ts` configures the Composition API (`legacy: false`) and sets `fallbackLocale: 'en-US'`.

### 2. Locale files

JSON files live in `i18n/locales/` and use a nested namespace:

```jsonc
{
  "app": {
    "name": "Warehouse PDA"
  },
  "home": {
    "greeting": "Hello, {name}",
    "prompt": "What would you like to do?"
  },
  "login": {
    "title": "DocPal",
    "subtitle": "Warehouse PDA",
    "username": "Username",
    "password": "Password",
    "signIn": "Sign in",
    "signingIn": "Signing in…"
  },
  "status": {
    "receiving": { "pending": "Pending", "in_hand": "In hand", "clear": "Clear" },
    "picking": { "pending": "Pending", "picking": "Picking", "finished": "Finished", "issue": "Issue" },
    "box": { "open": "Open", "closed": "Closed", "verified": "Verified" },
    "measuring": { "pending": "Pending", "completed": "Completed" }
  },
  "errors": {
    "invalid_credentials": "Invalid username or password",
    "operator_not_signed_in": "Operator not signed in",
    "quantity_not_available": "Quantity no longer available in receiving",
    "quantity_exceeds_need": "Quantity exceeds picking order need"
  }
}
```

Keys are named after the page/component or the concept they describe.

### 3. Replacing hardcoded strings

Templates use `$t`:

```vue
<h1>{{ $t('home.greeting', { name: userName }) }}</h1>
<button>{{ $t('login.signIn') }}</button>
```

Composables and scripts import `useI18n`:

```ts
const { t } = useI18n();
const placeholder = t('receiving.searchPlaceholder');
```

Page titles from `definePageMeta({ title: '...' })` move into the locale file under a `meta` namespace, for example `meta.receivingTitle`. Pages read the title with `useI18n().t('meta.receivingTitle')` and either render it directly or pass it to `useHead()`. `definePageMeta({ title: ... })` is removed to avoid mixing translated and untitled strings.

### 4. Status labels

Create `composables/useStatusLabel.ts`:

```ts
export function useStatusLabel() {
  const { t } = useI18n();
  return {
    receiving: (code: string) => t(`status.receiving.${code}`),
    picking: (code: string) => t(`status.picking.${code}`),
    box: (code: string) => t(`status.box.${code}`),
    measuring: (code: string) => t(`status.measuring.${code}`),
  };
}
```

Any component that currently renders a raw status code switches to this helper. If a code is unknown, `vue-i18n` falls back to the code itself.

### 5. Error messages

Create a lightweight error-code helper in `composables/useErrorMessage.ts` (or extend the existing `composables/errorMessage.ts`):

```ts
export function useErrorMessage() {
  const { t } = useI18n();
  return (err: unknown) => {
    if (err && typeof err === 'object' && 'code' in err) {
      return t(`errors.${(err as any).code}`, (err as any).params ?? {});
    }
    return err instanceof Error ? err.message : String(err);
  };
}
```

DB helpers and composables switch from throwing raw English strings to throwing coded errors:

```ts
throw new Error('operator_not_signed_in');
// becomes
throw new I18nError('operator_not_signed_in');
```

`I18nError` is a tiny class that carries a `code` property and optional `params`:

```ts
export class I18nError extends Error {
  constructor(public code: string, public params?: Record<string, unknown>) {
    super(code);
  }
}
```

Existing call sites that display `error.value` use `useErrorMessage()` to resolve the text. Unknown errors continue to show their raw message.

### 6. Language switcher

Add `components/LanguageSwitcher.vue`:

- Reads available locales from `useI18n().locales`.
- Shows the current locale name.
- Calls `setLocale(code)` on change.
- Watches locale and writes `warehouse-locale` to `localStorage`.

`AppHeader.vue` adds the switcher next to the existing action buttons.

### 7. Bootstrapping the saved locale

Because `ssr: false`, client-only lifecycle is safe. In `layouts/default.vue` or a small plugin, on app mount:

1. Read `warehouse-locale` from `localStorage`.
2. If it is one of the supported locales, call `setLocale(saved)`.
3. Otherwise leave the default `zh-HK`.

A small composable `useLocalePreference()` wraps the read/write logic.

## File changes

- `package.json` — add `@nuxtjs/i18n`.
- `nuxt.config.ts` — register the module and options.
- `i18n/config.ts` — new `vueI18n` configuration.
- `i18n/locales/en-US.json` — new.
- `i18n/locales/zh-CN.json` — new.
- `i18n/locales/zh-HK.json` — new.
- `components/LanguageSwitcher.vue` — new.
- `components/AppHeader.vue` — include `<LanguageSwitcher />`.
- `composables/useStatusLabel.ts` — new.
- `composables/useErrorMessage.ts` — new or extended.
- `composables/useAuth.ts`, `useScanMatchers.ts`, `useMockOcr.ts`, DB helpers — switch raw error strings to coded errors.
- All pages and components — replace hardcoded strings with `$t` / `t()`.

## Out of scope

- Localized URLs or SEO language tags.
- Locale-aware date, number, currency formatting.
- Translating demo seed data (supplier names, part numbers, shelf codes).
- Translating the native Android app label (`appName` in `capacitor.config.ts`).
- Right-to-left (RTL) layout support.

## Testing

1. Run `pnpm install` and `pnpm nuxt prepare`; confirm no type errors.
2. Run `pnpm dev` and log in as `operator` / `DocPal2026!`.
3. Check every page in `zh-HK`, `zh-CN`, and `en-US`:
   - Static labels, buttons, placeholders, empty states.
   - Status badges (receiving, picking, boxes, measuring).
   - Error messages (e.g., wrong login, invalid scan quantity).
4. Confirm the language switcher updates the UI immediately and the choice survives a page reload.
5. Run `pnpm generate` to ensure the static export still builds for Capacitor.
6. Android unit tests for OpenCV crop logic remain unchanged.
