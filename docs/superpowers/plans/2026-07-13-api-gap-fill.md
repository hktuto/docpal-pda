# API Gap-Fill for Frontend Migration (Plan 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every gap between the Hono API and the web app's `WarehouseService` contract (51 methods) + auth + demo seed, so Plan 8 can implement the `api` adapter and flip the frontend off PGlite.

**Architecture:** All new endpoints return snake_case JSON (Plan 6 convention; the Plan 8 adapter owns the camelCase mapping). Auth is demo-grade: plain-text password compare, `actor_id` stays a trusted client param. Demo data comes from a frozen `seedSql` string generated by replaying the web's `seed-precalc.ts` in PGlite and projecting rows onto the API schema; the API seeds itself on empty startup and exposes a dev reset endpoint. Business logic (mismatches, issue reporting, OCR pick) is ported from the web `db/` modules onto the API's invariant primitives.

**Tech Stack:** Hono, better-sqlite3, drizzle-orm, node:test, pnpm workspace (`@warehouse/api`, `@warehouse/shared`).

## Conventions (read first)

- **Shell:** prefix **every** pnpm command with `cmd.exe //c` (plain `pnpm` is broken here):
  - Build: `cmd.exe //c "pnpm --filter @warehouse/api build"` — Tests: `cmd.exe //c "pnpm --filter @warehouse/api test"`. Do not edit `package.json`.
- **Commits:** commit directly to `master`, never push. Stage explicit paths only (`git add <paths>`, never `-A`); never stage pre-existing stray files (`apps/web/public/labels-data.json` M, `tmp_screencap_*.png` D, `apps/web/public/box-shelf-labels.pdf`, `apps/web/scripts/generate-box-shelf-labels-pdf.mjs`, `apps/web/utils/scroll.ts`, `ui.xml`–`ui5.xml`, `docs/superpowers/plans/2026-07-12-native-android-phase-1.md` untracked).
- **NodeNext:** relative imports end in `.js`. **Timestamps:** `now()` from `db/now.ts` (ISO 8601). **IDs:** global `crypto.randomUUID()`. **Transitions:** `logTransition` from `ingest/transition.js` (`{ entityType, entityId, fromStatus?, toStatus?, actorId?, note? }`).
- **Generated columns (never write):** `picking_items.remaining_qty`, `inventory_lots.available_qty`. **Maintained columns** change only via `db/invariants.ts` primitives (`recomputeReceivingItem`, `recomputePickingItem`, `recomputeLot`, `applyPick`, `createAllocation`, `linkAllocation`, `scanToPackage`).
- **Test backstop:** every state-changing test ends with `assertInvariantsHold(db)` from `db/invariants.guard.ts`. Isolated DBs via the `makeDb()` pattern from `db/measure.test.ts` / `db/goodsVerify.test.ts`.
- **Route tests** use the temp-`DATABASE_URL` + dynamic `await import("../index.js")` pattern from `routes/putAway.test.ts` (set the env var BEFORE the import; seed via a second better-sqlite3 connection).
- All helpers throw `HTTPException` (400 validation / 404 missing / 409 state conflict). Route handlers do not try/catch — Hono's default error handling maps `HTTPException`.
- **`verified` is INTEGER 0/1** in sqlite; better-sqlite3 returns numbers.
- **Schema evolution:** add new columns to the `CREATE TABLE` DDL in `db/tables.ts` AND add an `ensureColumn(sqlite, table, column, decl)` call in `createTables`. Mirror in the drizzle schema under `db/schema/`.
- **Response JSON:** snake_case keys everywhere (adapter maps to camelCase DTOs in Plan 8). ISO strings or null for timestamps; 0/1 ints for booleans.

## Scope boundaries (decided — do not re-open)

- **IN (Plan 7):** auth endpoints; seed generator + seed-on-empty + dev reset; receiving list/detail reads; mismatch CRUD; picking-rows bundle + transition-log reads; picking issue reporting (+ schema evolution); `applyOcrPick`; scan-candidate snapshot; stock-search endpoints; QR-template endpoint (+ schema evolution).

- **DECIDED (auth):** `POST /auth/login {username, password}` compares plain-text (demo parity with `pgliteAuth.ts` and Android `AuthRepository.kt`), returns `{ id, username, name }`; 401 on failure. `GET /auth/users/:id` returns the same shape for session restore; 404 unknown. No tokens, no middleware; `actor_id` remains a trusted client param.
- **DECIDED (seed):** a generator test in `apps/web/scripts/` replays `seed-precalc.ts` in PGlite and emits `apps/api/src/db/seedSql.ts` (`export const seedSql = "..."`). **Allocations are NOT ported** — after seeding, startup runs `allocateAll(db)` (the API engine allocates at RII granularity with `allocation_receiving_items` links) and `assertInvariantsHold(db)`. Seed-on-empty condition: `users` table empty. Reset endpoint: `POST /dev/reset` wipes all tables, re-runs seedSql + allocateAll + guard.
- **DECIDED (shapes):** `PickingByReceivingRow` stays snake_case (web already expects that). `getReceivingOrder` detail does NOT embed picking rows/packages/boxes/logs — those come from the bundle endpoint (`GET /receiving-orders/:id/picking`); the adapter composes the two calls.
- **DECIDED (mismatch pure functions):** `validateMismatchInputs`, `computeReceivedQty`, `assertCanApplyMismatchQty` move to `packages/shared/src/index.ts` (the web's `ReportIssueModal.vue` will import them from there in Plan 8). API mismatch logic imports from `@warehouse/shared`.
- **DECIDED (scan candidates):** one snapshot endpoint `GET /receiving-orders/:id/scan-candidates` returning `{ receiving_by_part_no: {...}, picking_by_part_id: {...} }` (mirrors `findReceivingCandidatesForOrder`/`findPickingCandidatesForOrder`). - **DECIDED (applyOcrPick on API):** no receiving-area lot dance. Ensure an order-level allocation `(picking_item_id, receiving_order_id)` covers the qty (create/increment + FIFO `linkAllocation` across RIIs with `available_qty > 0`), then call the existing `scanAllocation(tx, { allocationId, qty, actorId })` — its `receivingOrderId` branch already walks the links, applies picks, and creates packages.
- **DECIDED (QR templates):** add `suppliers.qrcode_qty_encoding TEXT` (schema evolution); endpoint `GET /suppliers/qr-templates` returns rows with non-null `qr_template`.
- **DECIDED (issue fields):** add to `picking_orders`: `issue_qty INTEGER`, `issue_pack_size INTEGER`, `issue_remark TEXT`, `issue_reported_at TEXT`, `issue_reported_by TEXT` (schema evolution; `issue_reason`/`issue_note` already exist).

```ts
import { Hono } from "hono";
import { HTTPException } from "hono/http-exception";
import type { Context } from "hono";
import { sql } from "drizzle-orm";
import type { LoginRequest } from "@warehouse/shared";
import { db } from "../db.js";

export const authRoute = new Hono();

async function readJson<T>(c: Context): Promise<T> {
  try { return await c.req.json<T>(); } catch { throw new HTTPException(400, { message: "invalid JSON body" }); }
}

interface UserRow { id: string; username: string; name: string | null }

function loadUserById(id: string): UserRow | undefined {
  return db.get<UserRow>(sql`SELECT id, username, name FROM users WHERE id = ${id}`);
}

authRoute.post("/auth/login", async (c) => {
  const body = await readJson<LoginRequest>(c);
  if (!body.username || !body.password) throw new HTTPException(400, { message: "username and password are required" });
  const user = db.get<UserRow & { password_hash: string }>(
    sql`SELECT id, username, name, password_hash FROM users WHERE username = ${body.username}`
  );
  if (!user || user.password_hash !== body.password) throw new HTTPException(401, { message: "invalid credentials" });
  return c.json({ id: user.id, username: user.username, name: user.name }, 200);
});

authRoute.get("/auth/users/:id", (c) => {
  const user = loadUserById(c.req.param("id"));
  if (!user) throw new HTTPException(404, { message: "user not found" });
  return c.json({ id: user.id, username: user.username, name: user.name }, 200);
});
```

/** Seed demo data when the users table is empty. Returns true when it seeded. */
export function seedIfEmpty(sqlite: DatabaseType, db: DbOrTx): boolean {
  const c = (sqlite.prepare("SELECT COUNT(*) AS c FROM users").get() as { c: number }).c;
  if (c > 0) return false;
  sqlite.exec(seedSql);
  allocateAll(db);
  assertInvariantsHold(db);
  return true;
}

/** Dev-only: wipe everything and re-seed. */
export function resetAndReseed(sqlite: DatabaseType, db: DbOrTx): void {
  sqlite.exec("PRAGMA foreign_keys = OFF");
  try {
    for (const t of ALL_TABLES) sqlite.exec(`DELETE FROM ${t}`);
  } finally {
    sqlite.exec("PRAGMA foreign_keys = ON");
  }
  sqlite.exec(seedSql);
  allocateAll(db);
  assertInvariantsHold(db);
}

### Task 8: OCR pick (`applyOcrPick`)

One scan of a supplier label (OCR'd by native Android) applies qty to a picking item directly from a receiving order — no receiving-area lot dance on the API. Reference behavior: `apps/web/db/ocrPicking.ts:253-479`; API primitives to reuse: `linkAllocation`, `scanAllocation`, `applyPick`, `recomputeReceivingItem` in `apps/api/src/db/pickScan.ts` (read it fully first) and `apps/api/src/db/allocations.ts`.

**Files:**
- Create: `apps/api/src/db/ocrPick.ts`
- Modify: `apps/api/src/routes/picking.ts` (`POST /picking-orders/:id/ocr-pick`)
- Test: `apps/api/src/db/ocrPick.test.ts`

**Algorithm** (all in one transaction):
1. Validate `qty` positive integer (400). Order `:id` exists and RO is `in_hand` (404 / 409). Picking item exists, belongs to this order (404).
2. The item's part must appear in some `receiving_invoice_items` of the RO (else 409).
3. Remaining check: `qty <= pi.qty − pi.picked_qty − pi.scanned_not_boxed_qty` (else 409).
4. Part-level availability: `Σ rii.available_qty` for that part in the RO − unboxed scanned (per existing pickScan availability logic — reuse the same query shape `pickScan.ts` uses) must be ≥ qty (else 409).
5. Find-or-create the order-level allocation `(picking_item_id, receiving_order_id = :id)`: `left = max(0, qty − existingTotal)`; if `left > 0`, create top-up allocation for `left`, then assert `assertUnallocatedDemand` the way `pickScan.ts` does before linking.
6. FIFO link via `linkAllocation` across RIIs of that part with `available_qty > 0`, ordered by `ro.delivery_date ASC NULLS LAST, ri.invoice_no ASC, rii.date_code ASC NULLS LAST`; leftover after linking → 409.
7. Call existing `scanAllocation(tx, { allocationId, qty, actorId })` — its `receivingOrderId` branch walks the links, `applyPick`s, creates packages per link, handles pending→picking transition.
8. Return `{ package_ids: string[] }`.

Route body DTO `ApplyOcrPickRequest`: `{ picking_item_id, qty, date_code?, lot_code?, coo?, cow?, actor_id? }`. The `date_code/lot_code/coo/cow` are accepted (client sends them from the OCR parse) but allocation is FIFO — do not filter by them; they're informational only (matches web behavior).
