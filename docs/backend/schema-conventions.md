# Schema Conventions and Keys

Reference detail for the backend data model conventions. Catalog: `schema-tables.md`; DDL deltas: `schema.md`.

## Table conventions

every table has an `id` text PK (UUID v7 via `newId()` in `src/db/id.ts` / `app_uuid_v7()` in SQL; exceptions: bigserial event-cursor tables, `BOX-*` box labels) and carries `created_date`/`last_update_date` (named `creation_date` on `parts`/`suppliers`/`supplier_profiles`/`org_info`).

## Business keys and scan parsing

`parts.part_no` is NOT unique — `wcl_item_no` is the NOT NULL UNIQUE business key; the UUID `id` is internal-only; `brand` is a plain-text supplier-code copy (no FK). Natural keys elsewhere: `receiving_orders.batch_no`, `picking_orders.id` (caller-supplied UUID; `order_no` is NOT unique). `supplier_profiles` holds PDA-local supplier QR fields and is NOT synced upstream; its `brands` (parts.brand values per supplier) scopes scan-template lookup — brand-matching templates are tried first, rest as fallback, and part matching is space-insensitive over the label's `itemId` and `wclItemNo` groups (spec `docs/superpowers/specs/2026-09-29-picking-scan-wcl-item-no-matching-design.md`); when a template has no `wclItemNo` group and the profile covers exactly one brand, both parsers derive `wclItemNo` as `<brand>/<itemId>` (ABLIC labels print only the bare MPN; parts are stored as `ABLIC/<mpn>`), and a scanned wclItemNo matching any candidate narrows the match pool to those candidates (spec `docs/superpowers/specs/2026-10-27-scan-single-brand-wcl-item-no-derivation-design.md`); and `normalizePartNo` (backend `src/db/scanParse.ts` + PDA `apps/pda/utils/text.ts`) also unwraps the TE Connectivity storage wrapper `AMP(<pn>)` / legacy `TE-AMP(<pn>)` so a scanned bare PN matches the wrapped `parts.part_no`. Its `qty_encoding`/`date_code_encoding` drive label-field decoding in `src/db/scanParse.ts` (+ the PDA copy in `apps/pda/utils/parseOcrScan.ts`): `koa_zeros` (qty), `koa_month_counter` (KOA segment 5 is the raw lot code whose leading digits are a rolling month counter 10→99 + day of month; counter→year/month comes from the `date_code_counter_periods` table — one row per 90-month cycle, seeded 2010-12/2018-06/2025-12 — and the decoder picks the latest candidate cycle not in the future of the scan date, so a rotated counter resolves to the past label; the raw value is preserved as `lotCode`; a counter rotation = inserting the next cycle's row via `/admin/date-code-periods`, no code change; spec `docs/superpowers/specs/2026-10-16-koa-date-code-periods-design.md`), `ncc_lot_ymmdd` (NCC 28-digit ITF labels capture drawing(6) + lot(13) + qty(5) + serial(4); the lot is returned in 5–7–2 groups and its leading `YMMDD` becomes the ISO week date code, resolving the year digit to the latest matching year not after the scan year; fixed-width assertions prevent 28/32-digit boundary backtracking, and 32-digit NCC_KTD parsing is preserved, and drawing-no → item-no lookup remains future work; spec `docs/superpowers/specs/2026-10-26-ncc-lot-date-code-design.md`), `yyyymm_midmonth` (ABLIC/SII $-reel YYYYMM month date code anchored on the 15th of the month and decoded to the ISO week date code — `202606` → 2026-06-15 → WWYY `2526`; spec `docs/superpowers/specs/2026-10-27-scan-single-brand-wcl-item-no-derivation-design.md`), `yywwd` (TE Connectivity 5-digit DC = YYWW + day digit, day dropped and the YYWW pair rendered in the label format — `26374` → WWYY `3726`), `ymmdd` (COPAL reel labels: the serial field's 5-digit `YMMDD` prefix is captured as the lot code and decoded to the ISO week date code with the same one-digit-year rule as NCC; the COPAL template also appends its `resCode` group to the itemId because parts.part_no stores the resistance code — `SM-3 TW` + `104` → `SM-3TW 104`). Its `outdated_limit_months` (nullable integer months, NULL = no check, create defaults 12, migration backfilled 12) sets the per-supplier outdated date-code limit (spec `docs/superpowers/specs/2026-10-07-supplier-outdated-datecode-warning-design.md`): a picking/put-away scan whose label date code (label format — WWYY for `dateCodeFormat=wwyy`; canonicalized to YYWW for the check) is older still succeeds but records an `outdated_scan_warnings` row and returns `outdatedWarning` (PDA alert dialog + order warning chips), and order completion is held — the explicit picking finish 409s `unresolved_outdated_warnings` (boxing never finishes an order since 2026-10-16), receiving auto-clear held — until an admin resolves the order's warnings (`GET /admin/outdated-warnings`, `POST /admin/outdated-warnings/resolve-order`, which re-runs the held receiving clear; logic in `src/db/outdated.ts`). `user_profiles` holds the PDA-local per-user sub-inventory scope (keyed by `username`, no FK so a profile can pre-exist the `users` row), applied to the receiving/picking list+detail reads and the `GET /stock-search/options` locations list via `src/db/user-scope.ts` (a NULL `sub_inventory_code` acts as every sub-inventory of its org — visible when the scope covers any sub-inventory of that org; empty scope = unrestricted).
The six PDA-queue tables (`receiving_orders_cn`, `picking_orders`, `put_away_tasks`, `put_away_tasks_cn`, `verify_tasks`, `shipping_boxes` — the measuring queue) carry a nullable `assignee` text column (username, no FK — an assignment may pre-exist the `users` row, same convention as `user_profiles`): NULL = visible to every user; set = only that username sees the task in the PDA list + detail reads (detail 404s), enforced server-side by `assigneeFilter(column, username)` in `src/db/user-scope.ts` (reads only — mutations, allocation and SSE unaffected). Admin-managed via `GET /admin/task-assignments?flow=` + `PATCH /admin/task-assignment` (`src/db/taskAssignments.ts`; audit row per change). Spec `docs/superpowers/specs/2026-11-01-task-assignee-design.md`.
