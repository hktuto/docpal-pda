# Verify / Measuring Re-scan (Aggregate)

`picking_packages.rescanned_qty` is the mode-agnostic re-scan credit — `POST /packages/:id/verify` accepts `{qty}` (default the package's remaining; capped increment; `verified`/`verify_verified` flags set per mode on first credit); completion everywhere is `rescanned_qty >= qty` (`completeVerifyTask` 409 `packages_not_all_rescanned`, `closeShippingBox` 409 `all_packages_must_be_verified`). The close that spawns the box's verify task resets the credit to zero (the verify pass re-scans from scratch), and `reopenShippingBox` resets flags + credit. A **labeling stage** sits between picking finish and measuring/verify (spec `docs/superpowers/specs/2026-10-28-picking-labeling-step-design.md`): when the `labeling` step is enabled and the finishing order matches ≥ 1 active `label_print_rules` row, `finishPickingOrder` sets `picking_orders.labeling_pending` (a queue on the PDA `/labeling` pages, cleared by `POST /picking-orders/:id/labeling-finish`) and defers the measuring-off verify-task spawn; `listMeasuringBoxes` and the spawn's cross-order gate additionally require `labeling_pending = false`, so a cross-order box waits for ALL its orders to clear labeling. When the `measuring` step is disabled and `verify` enabled (flow config), `finishPickingOrder` itself spawns the pending verify task on the order's still-open boxes (a cross-order box waits until every order in it is finished — the same gate as the measuring list), the verify pass runs on the open box, and `completeVerifyTask` closes it (no weights/size, ship_to destination fallback) so it can ship; the PDA finish navigates straight to `/verify` in that configuration. Client-side matching is aggregate — totals per part + batch fields, qty ≤ group remaining, FIFO partial credits (`apps/pda/utils/measuringAggregateMatch.ts` + `matchMeasuring` in `apps/pda/composables/useScanMatchers.ts`); `picking_packages.label_barcode` is traceability/display only and no longer drives matching (spec `docs/superpowers/specs/2026-10-03-picking-scan-truth-and-aggregate-verify-design.md`). The batch fields anchor to the pick-time scanned values (`picking_packages.scanned_date_code/scanned_lot_code/scanned_coo/scanned_cow`, stored by the pick scan since 2026-10-14), falling back to the stored source snapshot for legacy NULL rows — so a verify re-scan is judged against the physical label that was picked, not upstream lot data. The pick scan itself validates batch fields client-side in `usePickingScanQueue` (`apps/pda/composables/usePickingScanQueue.ts`): COO/COW exact when the source carries them, date code equal-or-earlier (canonical YYWW compare — the scanned label code canonicalized per `dateCodeFormat` first; implausible/other-convention codes skip), lot code hard match when the source has one (spec `docs/superpowers/specs/2026-10-14-picking-scan-batch-validation-design.md`). **Label-aware verify (2026-10-30, spec `docs/superpowers/specs/2026-10-30-label-source-and-label-verify-design.md`):** per package, the verify/measuring pass splits by whether the package's order matches ≥ 1 active **internal** label rule (`labelMode` on the `GET /verify-tasks/:id` / `GET /measuring-boxes/:id` packages) — unlabeled packages (rule-less or external-only orders) show as per-item totals rows credited in any combination; label-mode packages additionally need their printed label scanned (`POST /verify-tasks/:id/scan-label`, raw-string equality against any param value of the recorded `label_prints` payload → `picking_packages.label_verified`), after which item scans pass their batch fields to `POST /packages/:id/verify` for a server-side hard compare (part_no/wcl_item_no + COO + date code, 409 `label_item_mismatch`); a box with a carton print record needs its carton label scanned too (`GET /verify-tasks/lookup-by-label?raw=` — the PDA verify-list scan tries this before box-id matching — stamps `shipping_boxes.carton_label_verified`). `completeVerifyTask` adds 409 `labels_not_all_verified`; `reopenShippingBox` resets the label/carton flags with the rest; packages never actually printed fall back to plain aggregate matching. The PDA side: two sections in `components/MeasureBox.vue` (labels-to-verify per package + items-to-re-scan grouped per part/batch via `apps/pda/utils/verifyDisplayGroups.ts`), label-first scan dispatch, external rules as info rows in `LabelPrintRulesPanel.vue`.
