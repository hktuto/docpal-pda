# Label Printing

Upstream print-service API doc: `print-service.md`.

`/print/*` (`src/routes/print.ts` + `src/print.ts`) proxies the label-printing-center print service — printer list, template dynamic print, direct file print, job status (no preview). Base URL from `PRINT_API_BASE_URL` (default `http://192.168.5.116:9003`); upstream errors → 502. Upstream API doc: `docs/backend/print-service.md`. The `label_print_rules` table (managed via `/admin/label-print-rules`, spec `docs/superpowers/specs/2026-09-16-label-print-rules-design.md`) configures which template a picking label uses; `POST /admin/label-print-rules/test-match` previews draft conditions against picking orders via the evaluator `src/db/labelPrint.ts` (`testLabelPrintRuleMatch`). The PDA picking-finish flow consumes the rules via `GET /picking-orders/:id/label-print-rules` (`resolveLabelPrintRulesForOrder` in `src/db/labelPrint.ts` — JS evaluation of the same condition semantics, first active rule by ascending priority per `label_type`; each match carries `labelCount` computed route-side), then prompts the operator to print (`components/picking/LabelPrintPrompt.vue`) via `POST /picking-orders/:id/label-print` — param conversion is backend-side in `src/db/labelPrintParams.ts`: a per-`print_template_id` converter registry (empty by default) with a label-type superset builder as fallback, batch fields anchored to the packages' pick-time scanned values, printed with the template's default printer; reprint via the picking detail's "Print labels" header action; specs `docs/superpowers/specs/2026-10-27-picking-finish-label-print-prompt-design.md`, `docs/superpowers/specs/2026-10-29-backend-label-print-conversion-design.md`). Rules carry `label_source` (`internal` default | `external` — customer-provided label: PDA shows an info row with no print button, the print endpoint rejects with 409 `label_rule_external`), and every successful print (reprints included) is recorded in `label_prints` (rule/template/printer, `expected_label_count`, jsonb `payload` rows linked per `packageId`/`shippingBoxId` to what the label was generated for) — the recorded content is what label-mode verify matches scanned labels against (spec `docs/superpowers/specs/2026-10-30-label-source-and-label-verify-design.md`).
